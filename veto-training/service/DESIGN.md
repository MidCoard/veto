# Trainer UI

React 18 and Material UI own this standalone training console. `web/src/main.tsx`
creates the MUI theme; controls use MUI defaults and layout uses `sx`. Do not add
parallel button/input/dialog CSS. Match Veto's graphite/cyan console and 8px thin
scrollbar across document, dialogs, tables and dropdown menus. Dropdowns use a compact elevated popover with small items and cyan selection, not a flat mobile sheet. A narrow desktop navigation rail,
compact grouped lists and dense forms replace stretched cards; narrow screens stack.
No redundant branding or instructional banners. Interactive controls have distinct hover/focus states, selected navigation uses an accent bar, semantic status chips use restrained color, and dialogs retain elevation. Long paths remain readable without
inflating list rows. Python serves the Vite build from `web/dist`; training remains in
independent processes. Main Veto UI is outside this migration milestone.

The Model tab has one Add Model dialog for Hugging Face downloads and existing local content; both feed the same catalog and retain task/run references. Remove Model permanently deletes the actual model after full-path irreversible confirmation, including complete Hub cache entries. Bound tasks remain listed in the warning and need a replacement model; they do not block deletion. Completed registered downloads are hidden, and GGUF is inference-only. Task deletion removes configuration only. CreateTask selects registered models and active managed datasets only. Dataset paths and JSONL source selection are not task-form controls; JSONL import belongs to Dataset management. Query-string navigation preserves the selected page on reload.

Profile saves use a scoped 100KB reserve check rather than a full accounting-tree scan; training launch retains full checks. CreateTask uses sectioned Paper/tinted headers and accessible labels/placeholders consistent with the sample reader. No-op polling compares complete snapshots so unchanged revisions do not hide live progress. The service supervisor captures bounded process output and exit codes and restarts failures with persistent capped backoff. Epoch-start events include max_steps, batch size, accumulation, effective batch and learning rate so the UI can show 0% before the first optimizer log. Training and export are separate progress stages: training percentage never represents a usable artifact. The UI switches to merge/GGUF export progress with an indeterminate state until converter tensor counts arrive, then shows actual current/total tensor progress. Only completed artifact registration displays 全部完成 ·100%. CreateTask chooses an owner template (Core screening or Secret), preserves editable settings, and saves without launching. It selects registered trainable models by display name; other local models are registered on the Model page first. Existing unregistered recipes remain usable, while GGUF is not trainable. New tasks default to an active managed dataset compatible with the owner template. Managed-dataset selection is restored from frozen snapshots when editing, and template changes preserve user-entered task names. Task forms have no JSONL/path source controls. A selected managed dataset owns the prompt format; no independent format selector remains active. Edit affects future runs only. Each task requires a user-selected output directory; runs create unique children there without a hard-coded repository model path. The path appears in start confirmation and run details, with target-volume checks. Saving validates fields without creating output; every start automatically validates files and runtime prerequisites. These checks do not claim model quality. Completed runs expose model artifacts and register them in Models; deployment is separate.

All task cards show cached train/validation nonblank JSONL record counts. Counting does not imply semantic validation. Automatic validation errors appear in the action dialog. MUI theme uses compact desktop controls, 4px corners, flat selected tabs and no ripple, with visible keyboard focus.


Dataset management shards JSONL files at 1,000 records or 32 MB, with file-level split, enable/disable and permanent deletion. A bounded record dialog navigates one record at a time, renders instruction/output and message content with react-markdown/remark-gfm, and edits source text and tool arguments without whole-record JSON editing. Every record offers a full JSON inspection mode, and each role message has its own raw/rendered switch using compact MUI toggles: system defaults to Markdown, user to the complete raw JSON message with optional Markdown content rendering, and assistant to JSON/native tool-call cards. The structured editor can add/remove messages, tool definitions and assistant calls. Native dataset version 5 stores unique full tool definitions in dataset.json and tool_refs names in each record. Record view/editor exposes editable references; native imports normalize definitions into the manifest, and snapshot export expands references into full native tools. Definition editing changes only the manifest atomically and preserves tool names so references/calls cannot diverge. Dataset-level add_definition creates a validated definition with zero initial references through a revision-checked atomic manifest write. Editor roles use clickable reader-style badges. Back to View keeps the record dialog open and uses inline discard confirmation instead of a nested dialog. Dirty state compares canonical record content, so add-then-delete does not prompt. Role cards use compact tinted badges and semantic role accents, the rendered label is 阅读, and tool definitions/calls also have independent reading/raw views. Message chrome uses a single tinted header with badge, toggle and explicit expand/collapse controls rather than a crowded Accordion arrow; message bodies avoid redundant nested panels and captions. Filename and a compact previous / editable-current / total / next pager form one quiet record toolbar, with Enter/blur navigation and no separate jump button. Editor fields use accessible names, placeholders and section captions rather than duplicate floating labels. Saving keeps the record dialog open, refreshes the persisted record and shows its file. Numeric record-number jump complements previous/next navigation. An assistant with empty content and no tool_calls property displays a concise no-call state; the obsolete JSON-text empty-call shape is rejected and current managed native shards migrate atomically without changing frozen exports. Every collapsed role shows a content or call preview. The structured editor uses the same role accents, tinted headers and spacing as the reader. Markdown source, tool definitions and unknown fields remain inspectable. Headings, lists, tables, quotes and fenced code use compact MUI styling; raw HTML and automatic remote images are disabled. JSON object/array text and tool schemas retain syntax-colored JSON. Record updates validate native message structure and publish a replacement shard with an atomic manifest revision. The table uses fixed proportional columns at desktop widths so file actions and status labels remain visible without horizontal scrolling; narrow screens retain contained table scrolling. Training policy supports fixed epochs (early.stopping.patience=0) and dynamic early stopping (positive consecutive non-improving epochs). Patience is propagated through service/Java/Python, included in checkpoint signatures and logs, and dynamic-only in the task UI. The UI shows micro-batch × accumulation = effective batch. Saving a task automatically creates a fixed snapshot of enabled files; existing runs remain unchanged. Legacy and oversized current stores migrate through journaled staging, retaining recycled records in disabled files. No manual snapshot or recycle-bin action remains. Reuse MUI dialogs and controls.

Models supports Hub download, explicit pause/resume and automatic registration after complete download. Tokens are ephemeral, never stored in download metadata. Tasks may choose a managed dataset; save freezes train/validation exports. Runs expose bounded local logs, immediate stop, archive and restore. Dataset import accepts a browser file or a server path; archives retain samples and snapshots.

Completed runs show human task names and currently existing artifact filenames only; deleted files are not presented as available results. Full paths remain in model management and the output-directory disclosure. Hide the completed progress bar, repeated completion message and empty resume section; keep training and validation loss separate. Failed/interrupted records without recovery use concise current-state text rather than stale historical prose. MUI Tooltips explain actions, and a persisted light/dark choice uses Veto-compatible tokens.

Failed or interrupted exports expose retry only when a complete merged model, saved adapter or optimization-finished checkpoint exists. Export never reruns optimization; finished checkpoints are export sources, not ordinary resume inputs. Explicit conversion retry replaces only the current run's expected partial GGUF outputs. Ordinary confirmations and asset references use task/run names rather than internal run IDs.

Run lifecycle transitions and numeric metrics are independent: progress events cannot change pause_pending or pausing back to running, and late events from a previous launch are ignored. Lifecycle events are never dropped behind numeric progress; bounded queues coalesce only superseded metrics. current_step and completed_step are separate so an in-flight step is not counted as complete. A new checkpoint is checksummed and marked complete before bounded retention removes an older complete checkpoint; an interrupted save cannot delete the last valid recovery point. GGUF converter and quantizer write bounded temporary files and publish final filenames only after successful exit and nonempty-output validation. Export completion requires a successful current conversion, never the mere presence of a partial GGUF left by a failed attempt.

Microbatch diagnostics record monotonic wall/process/thread timing and CPU collator token metadata without adding CUDA synchronization. An optimizer step running longer than 120 seconds dumps Python thread stacks into the bounded worker log, including post-microbatch loss checks and optimizer waits. Diagnostic events are coalesced as non-state metrics and never advance UI step counters.
